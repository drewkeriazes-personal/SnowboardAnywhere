# PR shepherd (FEAT-324, FEAT-326)

Drew merges open PRs one at a time, often several within a minute or two. Each merge can leave the others conflicting with `main`. This skill keeps them all mergeable so he never waits on a conflict, in both repos: the game (drewkeriazes/SnowboardAnywhere, tag `SA`, main checkout `C:\Users\Drew\git\SnowboardAnywhere`) and the pipeline (drewkeriazes/MapPacker-SnowboardAnywhere, tag `MP`, main checkout `C:\Users\Drew\git\MapPacker-SnowboardAnywhere`). `repos.sh` lists them; `SHEPHERD_REPOS` overrides it. The skill lives in the game repo; MapPacker's `.claude/skills/pr-shepherd/` only points here (FEAT-327).

You are the **coordinator**. You do not resolve conflicts yourself; one background agent per PR does, and you keep it busy. The agents follow the **Agent brief** below; point them at this file instead of retyping it. Two scripts sit next to this file: `survey.sh` (the PR table) and `watch.sh` (wakes you when either repo's `main` moves). Call them by the absolute path of this file's folder, since the main checkout may not have pulled the skill yet.

What to expect (first live run, 2026-11-16): Drew merged 13 PRs in about 20 minutes, often three or four inside two minutes. An agent round took 2 to 4 minutes, half of it the GPU push, so a PR can conflict again before its agent finishes; one PR (#689) needed three rounds. Agents read this file fresh each time they start, but your copy is the one loaded when the skill was called: if the skill changes during a run (a push to its PR), read it again before the next step.

## Coordinator loop

1. **Survey.** `bash <skill-dir>/survey.sh` prints one row per open PR in both repos: repo tag, number, `mergeable`, draft, branch, failed checks, worktree (looked up in that repo's own clone). It waits (up to 6 x 20 s) until GitHub has finished computing `mergeable`: right after a merge every PR reads `UNKNOWN` for 20 s or more, so a quick second `gh pr list` is not enough. Run it from anywhere.
2. **Dispatch.** Spawn one background agent (`general-purpose`, `name: "sa-<number>"` or `"mp-<number>"`, since PR numbers overlap between the repos) per PR that is `CONFLICTING`, still `UNKNOWN` after the survey gave up, or has a failed check, all in one message so they run at once. Skip MapPacker publish PRs (branch `publish/<slug>-v<N>`, label `publish`): `publish-merge.yml` owns them, and a hand push after the `automerge` label is refused as untrusted; tell Drew if one conflicts. Prompt: "You are the pr-shepherd agent for PR #N in <owner/repo> (branch B, worktree W[; it is a draft, leave it draft]). It currently <conflicts with main / has failed check X>. Read <absolute path to this SKILL.md>, section "Agent brief", and follow it exactly." A PR that is `MERGEABLE` with no failed checks gets no agent until it needs one, even if it is behind `main`: GitHub does not require branches to be up to date here, so behind is fine. Tell Drew which PRs got agents and which were already clean.
3. **Watch.** Start `bash <skill-dir>/watch.sh 60 240` with the Bash tool's `run_in_background`, never with `&` or `disown`: a detached watcher wakes nobody and its output is lost (the first run did this once by mistake, and missed nothing only because a second watcher was running). Keep exactly one watcher running. It exits when either repo's `main` moves or an open PR closes, printing `CHANGED: <tags>`, then per repo `<tag> main (moved|same): old -> new` and its `closed`, `opened` and `open now` lists. A PR opening does not wake you (in the first live run that was the only false wake); it shows up in the next report and the next survey. Do not poll it; you are woken when it exits.
4. **React.** When it wakes you:
   - **Closed PRs** drop out. If one's agent is still working, stop it (TaskStop).
   - **`main` moved:** run `survey.sh` again. Drew's merges come in bursts, so expect several PRs at once.
     - A PR now `CONFLICTING` with an agent from earlier: `SendMessage` to `sa-<n>` / `mp-<n>`: "PR #N conflicts with main again: main moved to <sha> (#A, #B merged). Repeat the Agent brief from step 2, push, and report." Sending to a finished agent resumes it with its context, which is what you want: it already knows the PR.
     - A PR now `CONFLICTING` with no agent: spawn one as in step 2.
     - An agent **still working** when `main` moves again: `SendMessage` it "main moved to <sha> while you were working; fetch and merge the newest origin/main before you push". The message waits for the agent's next tool round, so it may arrive after the push; the agent then merges again and pushes a second time. That's fine; don't spawn a second agent for the same PR.
     - A newly opened PR in the table is handled like any other row.
     - **Across the repos:** MapPacker's `format-check` compares its PRs with the game's `main`, and the pack format is the contract between them. When the game's `main` moved with a change under `game/src/pack/`, rerun `format-check` on the open MapPacker PRs (`gh run rerun <run-id> -R drewkeriazes/MapPacker-SnowboardAnywhere`) and send an agent to any that then fail. A MapPacker merge never makes a game PR conflict, but it can be the partner a game draft waits on (as #663 waited on MapPacker's FEAT-243 side): say so when one lands.
   - Restart `watch.sh`. On `TIMEOUT` with exit 0 (nothing changed), restart it too, unless Drew has gone quiet for hours (then ask whether to keep going). Exit 1 means `gh` answered for neither repo: tell Drew (`gh auth status`, network) instead of restarting. One repo failing does not stop the other: the watcher keeps watching the repo that answers, names the failing one on stderr, and ends its report with `UNREACHABLE: <tag>(never answered|last poll failed)`; pass that on to Drew (a token without access to MapPacker, a rate limit) and keep going.
5. **Check each report.** When an agent reports a push, confirm the PR reads `MERGEABLE` (`gh pr view <n> --json mergeable -q .mergeable`). If it says it fixed something the merge broke beyond the conflict markers, relay that to Drew as worth a look (in the first run, #663 merged without a textual conflict but no longer compiled; the agent's fix was right, but it changed code).
6. **Stop** when no PRs are left open or Drew says stop: stop the watcher (TaskStop), let running agents finish, and summarise each PR's state (merged, mergeable, still blocked and why). The last PR open is often this skill's own or the coordinator's; keep watching until it closes too. The summary lists the PRs merged in order, which ones needed agents and how many rounds, and every fix an agent made beyond conflict markers, so Drew can check those on `main`.

Report each event in a line or two: "#704 conflict after #702 merged; agent resolving", "#689 pushed a1b2c3d, mergeable". Relay anything an agent couldn't settle as a question for Drew. Don't repeat an agent's whole report; the files and how both sides were kept is enough.

Don't touch either main checkout (other sessions keep uncommitted work there), and leave `spotify-private` alone (CLAUDE.md: Drew merges it himself).

## Agent brief

You own one PR. Work only in its worktree; never in a main checkout or another PR's worktree. The coordinator tells you the repo. Where the steps differ, **SA** is the game (drewkeriazes/SnowboardAnywhere; follow its `CLAUDE.md`) and **MP** is MapPacker (drewkeriazes/MapPacker-SnowboardAnywhere; follow its `CLAUDE.md`).

1. **Find or make the worktree.** `git -C <main checkout> worktree list` shows the one on the PR's branch. If none exists, **SA**: `git worktree add ../wt<issue> <branch>`, where `<issue>` is the issue number in the branch name `issue-<issue>-<slug>` (not the PR number; for #727 on `issue-726-pr-shepherd` that is `../wt726`), and `<branch>` is the plain branch name (not `origin/<branch>`), so git makes a local branch that tracks the remote one. Then junction the worktree's `game/node_modules` to `C:\Users\Drew\git\SnowboardAnywhere\game\node_modules` with `New-Item -ItemType Junction`; never junction anything into `packs/`. **MP**: from `C:\Users\Drew\git\MapPacker-SnowboardAnywhere`, `git worktree add ../wt-mp<issue> <branch>`; nothing to junction (raw data is shared through `SBA_RAW_ROOT`, never copied or linked). Check it is clean (`git status`); if it holds someone's uncommitted work, stop and report instead of touching it.
2. **Sync with the PR branch.** `git fetch origin`, then compare `HEAD` with `origin/<branch>`. If the remote is ahead (Drew used "Update branch", or the review bot pushed), `git merge --ff-only origin/<branch>`. If they diverged, stop and report.
3. **Merge main.** `git merge origin/main` (merge, never rebase or force-push). If it conflicts, resolve every file by understanding both sides: read the PR's own diff (`git diff origin/main...HEAD` before the merge) and the main commits that touched the file (`git log origin/main --oneline -5 -- <file>`), and keep both intents. Never resolve by dropping the PR's change or main's without saying so in your report. What conflicted in the first live run, and what was right each time:
   - **Lists both sides appended to**: `BROWSER_CHECKS` / `PHYSICS_CHECKS` in `.github/workflows/checks.yml`, the CI table and test-tool lines in `docs/developer-guide.md`, URL params in `game/src/core/params.ts` (the `Params` interface and `parseParams`), fields and destructuring lines (`RideFrame.ts` `streaming()`, `installSimDebug` in `Session.ts`), import lines. Keep main's version of the line and add the PR's entries. For `checks.yml`, check the PR's new check still runs under main's job layout (since FEAT-322 a check not named as its own shard runs in the `rest` shard).
   - **Two changes to the same object**, such as a new-cell literal in `Rocks.ts` or `Vegetation.ts` that both sides gave new fields: take main's shape and add the PR's fields, then read the code that uses them to be sure the two features don't step on each other.
   - `package-lock.json`: take main's, and re-run `npm install` in the worktree only if the PR changed `package.json`.
   - **MP**: files a tool writes (`RELEASES.md` from `pipeline/releases.py`, a resort's `resorts/<slug>/` and `manifests/<slug>.json`) are regenerated with that tool rather than hand-merged when both sides changed them; say so in the report. A conflict on `FORMAT_VERSION` in `pipeline/packwriter.py` is a contract change between the repos: stop and report.
4. **Check, every time, even with no conflicts.** **SA**: `cd game && npx tsc --noEmit`. **MP**: `python -m pytest pipeline/tests` (about 5 s; the tests marked `game` read the sibling game clone). A clean textual merge can still break: in the first run main added a call to a function the PR deletes, which only `tsc` caught. **SA**: if the merge touched Python in `tools/`, run its tests too (for example `python tools/test_card_id.py`). Fix what the merge broke, keeping both intents; don't refactor beyond it.
5. **Failing checks.** If the PR has a failed check on its head (`gh pr checks <n>`), read the failed job's log (`gh run view <run-id> --log-failed | tail -80`) and fix it if the cause is in the PR or in the merge. If it is flaky or caused by `main` itself, rerun it once (`gh run rerun <run-id> --failed`) and report rather than patch around it.
6. **Catch up, then push.** Commit the merge with git's default message (add a second line naming the card id when you fixed something beyond the conflict). Right before pushing, `git fetch origin` again: Drew often merges more PRs while you work, and if `origin/main` moved, go back to step 3 so the push carries the newest `main`. Then, from the worktree with everything committed: **SA**: if the change touches `game/`, push with `node tools/ci/local_render_budgets.mjs --push` (about 2 minutes on the GPU; several agents running it at once worked fine; it refuses a dirty tree, a `stills` label, or stale `node_modules`). **MP**: if the change touches `pipeline/`, push with MapPacker's own `node tools/ci/local_render_budgets.mjs --push` (same flow; its dirty check counts untracked files, so park any fresh `resorts/<slug>/` or `manifests/<slug>.json` outside the tree first). Otherwise, in either repo, a plain `git push origin HEAD:<branch>`. Never push to `main`. Plain commit messages, no `Co-Authored-By` trailer.
7. **Report and stop.** Reply with: PR number, the `main` sha you merged, what conflicted and how you resolved each file, any fix beyond the conflict markers, checks run, the pushed sha, and anything left for Drew. Then end your turn. The coordinator messages you again when `main` moves; when it does, repeat from step 2 with the same care.

A draft PR is handled the same way; don't mark it ready. If a conflict needs a product decision (both sides changed the same behaviour in incompatible ways), don't guess: leave the branch unpushed, describe the two options, and stop.
